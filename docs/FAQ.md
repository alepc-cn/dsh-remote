# 常见问题 / 故障排查

## 添加设备后提示 401 / 认证失败

- 对方设备重启过、或重装过 DSH ⇒ 它自己的 token 变了；
- 到对方设备：设置 →「远程连接」→「本机地址/token」→ 复制带 token 的完整地址；
- 回到本机：设置 →「远程连接」→ 设备管理 →「修改」→ 把完整地址重新粘贴进去（地址里含 token）；
- 粘贴后马上就能用，不需要重启。

## 端口不通 / 页面打不开

1. 先在同一局域网用浏览器打开 `http://对方地址:端口/`，确认对方 DSH 的对外端口本身可访问；
2. 对方机器：确认插件「对外端口」已开启，且 Windows 防火墙 / 安全软件放行了这个端口；
3. 跨网络访问：插件不提供网络打通能力，需要自行准备可达链路（组网 / VPN / 反向代理等）；
4. 换过端口后，记得同步更新本机设备表里的地址。

## 切换设备后页面白屏 / 一直转圈

- 目标设备可能已关机或网络断开：先确认那台机器在线；
- 插件对"已知不可达"的设备会禁止切换并提示原因；
- 回到本机：按 **Alt+Home**（0.16.0 起），或在设备管理标题栏点「返回本机」；
- 仍无法恢复：关闭 DSH 后重新打开（不要反复点切换）。

## 升级插件后没有变化

- 覆盖 `lib/index.js`、`lib/client.js`、`package.json` 后需要**重启 DSH**；
- 版本号在 设置 →「远程连接」→「体检」里显示，可用来确认是否已升级。

## 白屏 / DSH 起不来怎么办

运行一键重置脚本（插件启动时自动放在数据目录）：
```
%USERPROFILE%\.dsh\dsh-remote-reset.cmd
```
它会：关闭 DSH → 备份并清掉卡住的 `Local Storage`（设备切换状态）→ 重新启动 DSH。
不会删除设备表和 token（它们在数据文件与凭据里），只是重置卡住的状态。

## 怎么查看 / 提供日志

- 设置 →「远程连接」→ 页面底部「诊断日志」：可**写入剪贴板 / 下载日志 / 清空日志**；
- 日志文件：`$DSH_HOME/dsh-remote.log`（Windows 默认 `%USERPROFILE%\.dsh\dsh-remote.log`），自动轮转、不含 token / 密码；
- **DSH 起不来时**：直接运行 `%USERPROFILE%\.dsh\dsh-remote-collect-logs.cmd`（插件启动时自动放置），它会把日志、崩溃日志和环境信息打包到桌面。

## 设备列表里有两台同名设备

- 一台是「本机」（自动识别，设备管理里已隐藏），另一台是你配置的远端条目；
- 如果确实重复配置了同一台机器，删除多余的那条即可。

## 更新提示显示"检查失败"

- 插件会访问 GitHub 查询最新版本；网络无法访问 GitHub 时会显示检查失败；
- 不影响插件任何功能；可从 Release 页面手动查看最新版本。

## 支持哪些 DSH 版本

见 README「兼容性」表；升级 DSH 后建议同步升级插件。
