# dsh-remote

在你自己的一台电脑上，直接用另一台电脑的 DSH：切换会话、用终端、取文件。

## 解决了什么

- 你可能有两台以上电脑各跑一个 DSH（设备A / 设备B / 笔记本…），以前要看另一台就得跑过去，或者在两个窗口之间来回切；
- 装上它：侧栏「自动化任务」那一组下面多一行**「设备 · …」**，点一下把当前窗口切到另一台，再点「本机」切回来；
- 附带两个跨机动作：把另一台上的文件**「另存为」**到本机；把本机的一条会话**「分叉到」**另一台接着聊（带最近若干条消息）。
- **「添加工作区…」跟着会话走**：在切到另一台的状态下新建工作区，弹出来的是**那台机器**的目录（不再是本机的文件夹窗口）。
- 默认是**局域网**场景（同一个 WiFi / 同一交换机）；需要**外网访问**时，自己做一层网络打通即可（见下）。

## 安装（每台电脑都要装）

```bash
dsh plugin --profile desktop add https://github.com/alepc-cn/dsh-remote/releases/latest/download/dsh-remote.tgz
```

装完**重启一次 DSH**，然后到 **设置 →「远程连接」→「配置」**：

- 填「**对外端口**」（默认 `19387`）—— 这就是**你其它电脑连你这台**时用的端口；
- ⚠️ 不要填 DSH 自己在用的端口（会提示你换一个）；填好后记得让这个端口**能被你其它电脑访问**（Windows 防火墙 / 安全软件放行一次）。

## 两台电脑怎么配（以 A、B 为例）

1. **先确认能通**：在 A 上打开 `http://B的IP:19387/` —— 应该出现 DSH 的页面（不是"拒绝连接"）。不通就先查 B 的对外端口和防火墙。
2. **在 B 上取 token**：设置 →「远程连接」→「**本机地址/token**」，复制那段带 token 的地址（形如 `http://B的IP:19387/?token=…`）。
3. **在 A 上加设备**：设置 →「远程连接」→「**设备管理**」→ 新增一条：
   - 名称：随意（如 `设备B`）
   - 地址：`http://B的IP:19387`
   - token：第 2 步那段地址里 `token=` 后面的字符串
4. **开始用**：A 的侧栏出现「设备 · 设备B」那一行 → 点它切到 `设备B`，再点「本机」切回来；终端、会话、另存为、分叉都跟着走。
5. **想让 B 也能切到 A**：在 B 上把 A 照第 2–3 步再加一遍（两边各加对面一条，就双向了）。

> 多台机器同理：每台上加"所有其它机器"各一条即可。

## 在另一台机器上新建工作区（「添加工作区…」）

切到另一台（右下角胶囊选了设备）之后，点「**添加工作区…**」：

- 正常情况下弹出的是**应用内**的目录浏览框，标题写着那台设备的名字，列的是**那台机器**的文件系统；
- 如果那台机器是「**系统对话框**」模式（Windows + DSH 只监听回环 = **默认**，它没有浏览器可浏览的目录后端），
  列表读不出来 —— 这时对话框会**用中文**说明是什么限制（不抛官方英文原文），并给两条能走的路：
  ① 上面列出**那台机器上已有的工作区目录**，点一下就选它；② 下面**直接输入**那台机器上的绝对路径（例如 `D:\work\项目`），
  点「用这个路径」—— 两条都照样把工作区建在**那台机器**上；
- **本机模式不动**：没选设备时，「添加工作区…」还是 DSH 原来的行为（本机的系统文件夹窗口）；
- **选中的就是本机自己那一台**（设备表里标着「本机」）时也**不接管**：那种状态等于没切走，照样是本机的系统文件夹窗口。

验收（用户视角、一次跑完）：

1. 前置：两台都装了本插件，A 上设置里加好 B 这台设备；
2. 操作：在 A 的窗口里用侧栏那一行「设备 · …」切到 **B**，点「添加工作区…」；
3. 观察1：**A 上不弹本机的系统文件夹窗口**；弹出的是应用内对话框，标题带 B 的名字，提示「这是对面机器（B）的文件系统」；
4. 观察2（B 支持浏览时）：能点进 B 的各级目录、能新建文件夹，点「用这个目录」后工作区建在 **B** 上；
5. 观察3（B 是系统对话框模式时）：对话框用中文说明限制；点「对面已有的工作区目录」里的一个，**或者**输入 B 上的绝对路径 →
   「用这个路径」→ 工作区建在 **B** 上；✅ **2026-10-15 真机实测：输入路径这种方式已成功在对面建出工作区**；
6. 反例：切回「本机」后，点「添加工作区…」必须还是本机原来的行为（我们不接管）。

## 局域网 / 外网

- **局域网**（默认）：第 1 步用另一台的**局域网 IP**（如 `192.0.2.10`）就行。
- **不同网络**（家里 ↔ 公司 ↔ 手机流量）：**插件不负责穿透**。你自己搭一层打通网络即可 —— ZeroTier / Tailscale / WireGuard / FRP / nginx 反代都行；打通后把「地址」填成穿透后的地址（例如 `http://192.0.2.10:19387` 或 `https://dsh.example.com`），填法完全一样。

## 注意

- 「**插件开关**」是总开关：停用后切换、终端、对外端口**全停**（这时只能在**本机**打开设置页把开关打回来）。
- 切设备的入口只有**侧栏那一行「设备 · …」**（点开是浮层菜单）：界面里**没有**右下角胶囊，垫片也**不插任何可见 UI**。
- **已知不可达的对端点不动**（浮层里那一行会灰掉，`title` 写着原因）：只给一句提示、**不会切换**，避免切过去白屏又没有入口切回来；没有那台的数据时（未知）照常允许切。
- **手机 / 浏览器经「对外端口」打开页面**时：状态点走 `GET /dsh-remote-view`（非 `/plugin/` 前缀，浏览器读得到）；这种会话里若当前选中的对端**连续两次**被判不可达，页面会**自动清掉选中设备并刷新回本机**。桌面端 / 本机 `127.0.0.1` 浏览**不会**自动弹回（你自己切过去的就留在那儿）。
- 「配置」块会用 DSH 自己的配置编辑器写 profile 里的两行：`webserver` 的**端口**、`connection` 的 **cookie 天数**（保存时会提示"重启 DSH 生效"）；**绑定地址一律不动** —— 对外访问由插件自己的「对外入口」承担，它不监听在 DSH 那个口上。
- 设置页和写接口**只对本机开放**；其它电脑从网络访问 `/plugin/` 会被拒（403）。
- 另一台的 token 一般在它重启后会变；插件会记住已建立的会话，通常**不用反复粘贴**。
- 「添加工作区…」的**可浏览**程度取决于对面那台：对面是系统对话框模式时只能**输入路径**（见上一节）；这一节只改本插件的**客户端**文件，改完**重载一次窗口**即可（宿主半没动，不必重启 DSH）。

## 0.12.0 有什么变化

- **版本号升到 0.12.0**（`package.json` / 宿主半 `VERSION` / 客户端半版本常量三处一致）。
- **新增一条能穿过「对外端口」的聚合口** `GET /dsh-remote-view`（**非 `/plugin/` 前缀**，守卫是 DSH 官方的"可信请求"判定）：
  返回与 `/plugin/remote/live` **同形**的 `{ at, self, peers }`，**只多一个 `version` 字段**（本机 dsh-remote 的版本号）。
  客户端半的取数顺序：`/plugin/remote/live` → 失败 / 403 / 形状不认识 → `/dsh-remote-view` → 两条都不行就保持上一次的快照（不清零、不画错）。
  跨机取数口 `/dsh-remote-live` 的语义**一个字没动**（它仍然只回本机自己，供对端拉取）。
- **版本可见**：客户端半拿到 `version` 与本机客户端半自己的版本常量比较，不一致时**只**在浮层那一行 / 侧栏那一行的 `title` 里
  写清"那台 dsh-remote x.y.z，本机 0.12.0，建议升级"，并写一条日志（只在变化时）；**不改变状态点的颜色**。
- **已知不可达 ⇒ 禁止切换**：目标对端在最近一次聚合里 `reachable === false` ⇒ **不刷新、不写键、不清未读**，
  只给一句"这台现在连不上（<原因>），先不切"；浮层里那一行灰化 + `title` 写原因。**没有那台的数据（未知）照常允许切。**
- **浏览器 / 手机场景恢复"可达性自愈"**：只在**非回环会话**（`location.hostname` 不是 `127.0.0.1` / `localhost` / `::1`，且是 http(s)）里，
  连续 2 次聚合判当前对端不可达 ⇒ 清掉选中设备并刷新回本机（复用既有的冷却 + 哨兵防回环，写不进冷却标记就绝不重置）。
  桌面壳（`dsh-app:`）与本机 `127.0.0.1` 浏览**一律不自动弹回**。
- **删掉胶囊死代码**：垫片里那段已停用的右下角胶囊面板（`mount()` / `ELEMENT_ID` / `removePill()` / `escapeHtml` 等）
  连同只为它存在的常量与注释**整段删除**；垫片运行期**一个 DOM 节点都不插**（隐藏的设备表 JSON 节点除外，它不渲染）。
  请求改写（`prefixPath()` / `rewriteUrl()` / fetch、WebSocket、XHR 三处 patch）与 `dsh-device-switch:*` 键**一个字节没动**。
